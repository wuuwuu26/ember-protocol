| File | Name | Height | Width | LOD0 | LOD1 | LOD2 |
|---|---|---|---|---|---|---|
| `chassis_light` | Light scout | 2.62 m | 1.44 m | 19,148 | 8,448 | 3,058 |
| `chassis_medium` | Medium general | 2.59 m | 1.67 m | 18,776 | 8,448 | 3,058 |
| `chassis_heavy` | Heavy assault | 2.48 m | 1.98 m | 18,404 | 8,280 | 2,944 |

**Geometry carries design constraints**: the light mech is narrow with many cooling fins (6 large fins), the heavy mech is wide with few (2 small fins). The player can read at a glance in the modding UI "does this machine run fast or take a beating".

**Each includes**:
- About 300 part objects, merged into a single mesh
- A **14-bone** skeleton, rigid parts bound with vertex group weight 1.0
- Smart UV unwrap
- LOD1 (45% decimation), LOD2 (18% decimation), in the separate collection `LODs`

**Skeleton hierarchy**:
```
root
└ pelvis
  ├ torso
  │ ├ head
  │ ├ shoulder_L -> upperarm_L -> forearm_L
  │ └ shoulder_R -> upperarm_R -> forearm_R
  ├ leg_L -> foot_L
  └ leg_R -> foot_R
```

## 7. UE5 Import Notes

### Units and Orientation (Measured and Verified)

**All 51 assets have passed round-trip tests** (re-imported into Blender to measure world bounding boxes):

| Variant | Width | Depth | Height | Verdict |
|---|---|---|---|---|
| `chassis_light` | 1.436 m | 1.076 m | 2.620 m | ✅ |
| `chassis_medium` | 1.670 m | 1.142 m | 2.590 m | ✅ |
| `chassis_heavy` | 1.978 m | 1.441 m | 2.480 m | ✅ |

**Conclusion: keep Uniform Scale at 1.0 when importing into UE, don't change it.**

FBX export uses Blender's **default settings** (`global_scale=1.0`).
Blender's default export already handles the meters → centimeters conversion correctly.

> ⚠️ **Do not manually set `global_scale=100`.** Measured, that makes every asset 100× too big
> (the mech becomes 259 meters). This pitfall has been hit before; `robotlib.export_fbx()` has detailed comments,
> read them before changing anything.

Orientation: −Y is the front in Blender; after FBX export it should be +X forward in UE.
Confirm once after import; if not, adjust `axis_forward`.

### Self-Check Method

After changing export settings, always run a round-trip verification:

```bash
cd tools/blender
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" \
  --background --python verify_fbx.py -- --dir ../../assets/out
```

Reading FBX vertex data directly gives the wrong conclusion — Blender writes the scale on the Model node's
`Lcl Scaling` while the geometry data itself remains in meters. Only a full round-trip gives the real result.

### Materials
Each asset uses 5–6 material slots: `M_Steel` / `M_SteelLight` / `M_Accent_*` / `M_Joint` / `M_Copper` / `M_Core_*` (emissive).
After import they need to be rebuilt as material instances in UE; procedural material nodes don't travel with the FBX.

### LOD
LOD1/LOD2 exist as separate objects (`SK_Chassis_*_LOD1` / `_LOD2`) and must be manually attached to LOD slots in UE's static mesh editor.

### Skeletons
Mechs have 14-bone rigid binding, enemies have 7–8-bone auto binding; both are directly usable for UE animation retargeting.
Modules and props are **not bound** (modules are attachments and don't need their own skeleton).

### Quarantined Old Assets
`assets/out/_superseded/` contains the v2 `robot_*.fbx`, **wrong size (100× too big) and superseded by `chassis_*` — do not import.**

## 8. Incomplete Parts (Honest List)

| Gap | Impact | How to fill |
|---|---|---|
| **No textures / UV not optimized** | UVs but no textures, seams not artist-adjusted | Need an artist to do materials and textures, scripts can't replace that |
| **Enemies and modules have no skeletons** | Can't be animated, import to UE as static meshes | Reuse the mech binding function, generate skeletons by part positions |
| **No collision** | Needs to be generated manually in UE | UE's automatic Physics Asset generation is good enough |
| **Landmark is only a massing model** | Can't be a final scene asset | Needs part-by-part detailing |
| **Topology is assembled primitives** | High face count, irregular edge flow, no deformation animation | Requires retopology if deformation is needed |
| **Assets without LOD** | Modules/enemies/props have no LOD | Reuse `make_lod()` for batch generation |
| **Five-area level not built** | Only pieces, no level | Needs assembly in UE |

## 9. Regenerating

```bash
cd tools/blender

# Full rebuild (~90 sec)
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" \
  --background --python build_all.py -- --out ../../assets/out

# Rebuild only certain categories
... build_all.py -- --only chassis modules

# Only output catalog sheets, don't re-import models
... build_modules.py -- --out ../../assets/out --sheet-only
```

To change numbers, only edit `variant_params()` / `CATALOG` at the top of each script — no need to touch the geometry code.
