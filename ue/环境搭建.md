## 二、决定性测试：实际编译一次

我直接跑了一次真实的编译命令，而不是猜：

```bat
Engine\Build\BatchFiles\Build.bat RobotGameEditor Win64 Development ^
  -Project="...\ue\RobotGame.uproject" -WaitMutex
```

**结果：**

```
Using bundled DotNet SDK version: 10.0 win-x64
Determining max actions to execute in parallel (14 physical cores, 20 logical cores)
Creating makefile for RobotGameEditor (no existing makefile)

Platform Win64 is not a valid platform to build. SDK validation failed:
  Sdk: not found. Required version 10.0.19041.0.

Result: Failed (OtherCompilationError)
```

**这个结果说明三件事：**

1. **引擎本身是健康的** —— UBT 正常启动、正确读取了 .uproject、成功生成了 makefile。
2. **卡点是 Windows SDK**，报错在 SDK 校验阶段，**连 MSVC 编译器都还没轮到检查**。
3. **`Result: Failed` 不是代码问题**，是环境问题。我写的 C++ 代码一行都还没被编译。

> 日志里的 `UbaStorageServer ... Access is denied` 是我在沙箱环境里执行导致的，
> 你自己在正常终端跑不会有这个问题（UBA 是编译加速器，即使不可用也不影响编译）。

## 三、解决方案

需要安装 **Visual Studio 的 C++ 构建工具**（含 MSVC 编译器 + Windows SDK）。

### 方案 A：VS 2022 Build Tools（推荐，体积小）

只装编译所需的最小集合，约 **7—12 GB**，无图形界面。

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools --source winget ^
  --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

`Microsoft.VisualStudio.Workload.VCTools` 就是「使用 C++ 的桌面开发」工作负载，
`--includeRecommended` 会自动带上 MSVC 编译器与匹配的 Windows SDK。

### 方案 B：VS 2022 Community（完整 IDE）

多一个图形界面与调试器，约 **15—25 GB**。如果你打算长期做 C++ 开发，
调试体验明显更好；如果只想要「能编译」，方案 A 就够。

```powershell
winget install --id Microsoft.VisualStudio.2022.Community --source winget ^
  --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.NativeGame --includeRecommended"
```

`NativeGame` 是「使用 C++ 的游戏开发」工作负载，UE 官方推荐。

> 两个命令都需要**管理员权限**，并且会下载数 GB 数据。

### 如果 UBT 仍然报 SDK 版本不符

手动补装指定版本的 Windows SDK：

```powershell
# 补装 Windows 11 SDK（覆盖 UE 5.8 要求的 10.0.19041.0 以上）
winget install --id Microsoft.VisualStudio.2022.BuildTools --source winget ^
  --override "--quiet --wait --add Microsoft.VisualStudio.Component.Windows11SDK.26100"
```

## 五、编译时的预期

这是我第一次用真实编译器验证这套代码，**大概率会有报错**。已经预判到的高风险点：

| 位置 | 风险 | 说明 |
|---|---|---|
| `URobotChassisData::IsDataValid` | 签名 | UE 5.4 前后从 `TArray<FText>&` 改成 `FDataValidationContext&` |
| `USkeletalMeshComponent::GetSkeletalMeshAsset()` | API 名 | 5.1 之后才替代 `SkeletalMesh` 成员 |
| `ASC->SetReplicationMode` | 必要性 | 单机项目里可能不需要 |
| `FGameplayTag::RequestGameplayTag(FName, bool)` | 参数 | 两参数版本存在，但要确认 5.8 未弃用 |
| `RobotCombat.Build.cs` 的 `GameplayTasks` | 依赖 | GAS 需要它，但某些版本要显式声明 `GameplayTasks` 模块 |

**把编译报错原样贴给我，我来逐条改。** 第一次编译有十几到几十个错误是正常的，
不说明架构有问题 —— 说明的是「还没人用真编译器过一遍」。

## 六、现在就能做的事（不等编译器）

即使没有 VS，这些也能进行：

| 能做 | 怎么做 |
|---|---|
| 打开引擎看资源 | 直接启动 `UnrealEditor.exe`，浏览引擎自带的示例内容 |
| 建一个纯蓝图测试工程 | 新建 Blueprint 项目，不需要 C++，验证引擎在你的机器上跑得动 |
| 导入并查看模型 | 新建工程后导入 `assets/out/chassis_medium.fbx`，**验证朝向与尺寸** |
| 跑核心循环原型 | `prototype/core_loop_prototype.html`，浏览器直接打开 |

**其中「导入模型验证朝向与尺寸」最值得先做** —— 它不依赖 C++，
但结果会影响后面所有资产：如果 FBX 的 `global_scale=100` 换算不对，
54 个资产都要重新导出。
