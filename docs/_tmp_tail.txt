 并建立了逐轮可复现的截图 + 统计管线。

## 一、战斗反馈：伤害数字与部位提示

### 现状诊断

| 现象 | 后果 |
|---|---|
| 命中只有一圈"四角括号"闪一下 | 看不出打了多少伤害、打的是哪个部位 |
| 部位被拆解时只听到一声响 | 不知道"我刚刚拆掉了什么" |
| 敌机站着时看不出哪条腿还剩多少血 | 核心玩法是"打部位"，但没有事前信息，只能盲打 |

### 做法

新增 `SRobotWorldMarkers`（`Source/RobotGame/Public/UI/RobotWorldMarker.h`），
一个**池化的绝对定位文字层**：

- 每帧把世界坐标投影到 1280×720 设计画布（和 HUD 同一套缩放公式），
  伤害数字从命中点往上飘 42px、0.85 秒淡出。
- 部位摧毁的那一击变成更大的橙红字：`拆解 躯干 15`，停留 1.35 秒。
- 准心指着敌机时，在它头顶显示 `右腿 42%`（按剩余血量变色：白→橙→红），
  瘫痪的目标显示 `已瘫痪 · 可回收`（避免玩家对着"尸体"一直补枪）。

### 关键设计决定：只显示"真实造成的伤害"

部位血量归零后再打，`ApplyDamageToPart` 会静默忽略（设计如此：溢出伤害不生效）。
如果 UI 按"发射了就打数字"，玩家会以为"打腿还有用"，实际上早没有收益了。

所以新增 `UPartDamageComponent::ApplyDamageByBoneEx()` —— 由**部位系统**
报告"实际扣了多少 / 是否拆解 / 核心是否被毁"，弹丸照这个结果画数字。
视觉反馈和规则用的是同一个数据源，不会各说各话。

### 踩坑记录：Slate 里没有"每帧改位置"的现成控件

- `SCanvas` 的子槽位位置是 `TAttribute`，外部每帧改要拿到 `FSlot*`，
  而 `GetChildren()` 返回的是基类 —— 5.8 里没有安全的公开反转办法。
  `SConstraintCanvas` 更适合静态 UI，不适合每帧移动。
- 最终自己写了 `SRobotFloatLabelLayer`（`Widgets/SPanel` 子类）：
  用引擎现成的 `TSlotlessChildren` 持有子控件，位置存在自己的 `TArray` 里，
  `OnArrangeChildren` 里按中心点摆放。**没有类型转换、没有重建 Slate 树**，
  十几簇数字同屏时也不掉帧。

### 验证

自动战斗截图里已经能看到 `拆解 躯干 15` 浮在命中点上方
（`docs/shots/2026-10-25/`）。

## 二、画面标定：从"感觉发白"到"过曝 0.1%"

### 原来到底有多糟（客观数字）

写了一个统计脚本 `tools/shot_stats.py`（亮度分位数 / 过曝 / 死黑 / R-B 比），
量第一轮基线：

```
mean=0.46  clip(>0.98)=30.4%  crush(<0.02)=17.3%  p50=0.17
```

**30% 的像素是纯白**，同时 17% 是纯黑 —— 画面里没有中间调，
这就是"看起来发白、细节全丢"的原因。光看截图感觉不出来，量出来一目了然。

### 修了什么

| # | 问题 | 根因 | 结果 |
|---|---|---|---|
| 1 | 所有硬边带一圈黑边（像描线） | 后处理 Sharpen 0.55 是反锐化掩模，对高对比硬边过冲，暗侧截断成纯黑 | 归零，交给 TSR 保边 |
| 2 | 地板整片进泛光，"糖霜感" | Bloom 阈值 1.0，而地板高光 p99 = 0.997 | 阈值提到 1.4 |
| 3 | 过曝 30% | 曝光 Bias 5.6 是在旧光照状态下标的（太阳曾 8~9 万 lux） | 逐档实测标定到 **3.0** |
| 4 | 画面偏暖发橙 | 太阳 22000 lux + 冷白，点光全暖黄，雾反照率偏褐 | 夜景布光：太阳 3200 lux 冷蓝、点光当氛围、冷雾 |

### 标定数据（同一机位、-ShotMode 去掉颗粒噪声）

| Bias | 均值 | 过曝 | 死黑 |
|---|---|---|---|
| 5.6 | 0.38 | 15.2% | 46.8% |
| 4.3 | 0.38 | 15.3% | 46.7% |
| **3.0** | **0.28** | **0.1%** | 50.9% |
| 1.8 | 0.18 | 0.0% | 52.5% |

5.6 和 4.3 结果一样，说明 4.3 仍在"高光撞顶"区间 —— 物理上太阳照到的地方
远超 1.0，减一点曝光只是让撞顶的像素少一点，画面仍旧一片白。

### 一个反直觉的坑

试过"关掉 `AutoExposureApplyPhysicalCameraExposure` + Bloom 归零，
让亮度只由光和材质决定"——结果**整屏 99.7% 纯白**。
这套工程的亮度只能走 `Manual + AutoExposureBias` 这条路。
（已写进代码注释，避免下次再试。）

## 三、验证管线（这轮最大的长期收益）

调色不能靠"再跑一次看看"，因为跑一次要 2—3 分钟（含引擎启动），
而且人眼 20 轮之后就会习惯发白的画面。所以这轮建了三条可复现的链路：

| 工具 | 用途 |
|---|---|
| `ue/shot.ps1` | 启动游戏 → 定时截图 → 自动退出，一条命令 |
| `ue/ScriptS/*.py` + `tools/ue_py.sh` | 在编辑器里改关卡数据（灯光/后处理/雾）并保存 |
| `tools/shot_stats.py` | 截图 → 亮度分位数 / 过曝 / 死黑 / R-B / 天空色 |
| `-ShotMode` 启动参数 | 关掉胶片颗粒与色散，让截图可逐像素比较 |

有了这三条，"这次改完是变好了还是变差了"变成一个可以回答的问题。

## 四、遗留

1. **画面仍是"夜景偏灰"**：过曝与黑边解决了，但中间调还偏少（p50 = 0.015），
   因为竞技场大部分是硬边方块 + 深夜天空。下一步应该加的是
   **局部暖光池**（地面光斑、机库门、警示灯），而不是继续加全局曝光。
2. **雾的效果不明显**：体积雾已开（冷灰蓝 1.6 消光），但当前机位看不出光柱 ——
   需要一盏**低角度聚光**穿过雾气才会出丁达尔。
3. **地面 albedo 偏高**：混凝土地面在 3200 lux 下仍接近纯白，可以考虑
   把 `M_Steel`（地面用）的基色压到 0.35 左右。
4. 伤害数字目前只有中文数字，没有暴击/弱点加成概念 ——
   如果以后加"弱点倍率"，`PushDamageNumber` 已经带 `bPartBreak` 标记，扩起来不难。
