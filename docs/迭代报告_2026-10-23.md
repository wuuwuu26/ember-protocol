# 迭代报告 · 2026-10-23

本轮目标：**敌人机体重做 + 场景精细化（含使用引擎自带资产）**。

---

## 一、敌人：从"方盒拼接"到"壳体 + 装甲切面"

### 问题

6 种敌人（巡逻 / 运输 / 巨像 / 园丁 / 气象 / 护卫）全部由 `R.box` 拼成。
加再多倒角，剪影也永远是直线段 + 直角 —— 远看就是一摞纸箱。
玩家机体上一轮已经换成曲面语言，敌我两套美术语言彻底割裂。

### 做法：三条规则

1. **主体轮廓必须是曲线**（椭球 / 圆柱 / 圆角棱柱）。直角只允许出现在
   "装甲板"这种本来就该是板的地方，且倒角段数 ≥ 3。
2. **每个关节 = 球窝 + 铜环**。球是轴、环是密封圈，这是机械件的通用语法。
3. **每种敌人必须有可辨识的剪影特征**（见下表）。

| 敌人 | 剪影特征 | 主要曲面件 |
|---|---|---|
| 巡逻机 | 悬浮球 + 单道大光环 + 环上吊舱 | 正球壳体、半径 1.5R 的环、三个喇叭口推进器 |
| 运输机 | 横卧货舱筒 + 三道加强环 | 沿 Y 的胶囊、弧形风挡、弯管吊臂 |
| 维修巨像 | 穹顶胸腔 + 双巨臂垂到膝下 | 椭球胸腔、三层反应堆环、锥形焊枪 |
| 园丁机 | 垂到膝上的围裙 + 圆帽 | 弧面围裙壳、帽檐圆盘、弯管壶嘴 |
| 气象机 | 比头还大的深碗雷达罩 | 半球碗（切 45%）、三杯风速计 |
| 重型护卫 | 双穹顶肩甲 + 上宽下窄的盾 | 半穹顶肩甲、盾形棱柱 + 底尖 + 盾心凸起 |

三角面：旧版 ~8k（方块）→ 新版 12k–34k（LOD0 含三级 LOD）。

### 顺带修的三个几何坑

1. **细杆被倒角吃掉**：`cyl(radius=0.009, bev=0.002)` 的倒角相对半径过大，
   整根杆在 `_finish` 里被吞掉 —— 巡逻机高度直接少 0.4m。加粗到 0.014。
2. **prism 的倒角上限**：`w = min(bev, min(size)*0.24)`，盾厚 9.5cm 时
   倒角上限只有 2.3cm，看起来仍是刀刃直角。厚度加到 20cm 才有真圆角。
3. **UV 不连续**：`auto_rig` 里原本用 Smart UV（按面片自动分岛），
   相邻面的 UV 方向随机 —— 程序化面板缝贴图一采样就撕裂。
   改成和玩家机体一致的**世界对齐立方投影**（`cube_uv`，1 UV = 1.2m）。

### 新工具：引擎内检阅模式

`-ReviewEnemies`：把场上 5 台敌人摆成一排、冻结 AI、隐藏玩家、
固定机位、自带三点布光 + 把太阳转到正面光。

为什么必须做：编辑器视口既没有后处理也不代表游戏光照；
而玩家视角（2m 高、贴地、背后）根本看不全机体。

⚠️ 检阅模式会转太阳方向，曝光需要单独降档：
`-ReviewEnemies -Bias=2.6`（正常游戏是 6.0）。

## 二、场景：不是缺资产，是缺摆放

### 核心发现

关卡 184 个 Actor 里，150 个是地面板 / 围墙 / 天桥 / 立柱，
**道具一个都没摆**。而 `/Game/RobotGame/Art/Props` 里
10 种道具（集装箱、货架、油桶、废料、供应箱、管道、救援舱、终端…）
早就做好了 —— 从建模到导入全都完成，就是没放进关卡。

`place_props.py` 按"堆场"生成：12 个区域，每区给道具类型 + 密度，
网格 + 固定种子抖动（±22cm、随机朝向、±8% 缩放），集装箱允许叠两层。
**避开玩家主通路**（|y| < 600 不放东西）。共 54 个道具。

### 引擎自带资产：星空

`/Engine/EngineSky/T_Sky_Stars` 直接接进 `M_SkyDome`：
方向向量的 XZ 投影当 UV（水平环绕），按 `dir.Z^1.6` 衰减 ——
地平线附近自动没有星星（真实夜空也是这样，被大气消光吃掉）。

这是本轮唯一真正"用引擎自带资产"的地方，也是收益最直接的：
纯渐变天空在夜景里是"一块布"，加一层星星立刻有纵深。

### 远景塔：建模完成，摆放未收敛

`build_backdrop.py` 做了三种场外剪影（烟囱塔 34m / 桁架塔 26m / 储罐群 17m），
但摆放试了三版都不对：
- 3000cm 处 → 塔比玩家还大，挡住半个画面
- 7000cm 处 → 塔脚悬空（墙外没有地面）
- 补了 280m 外围地面后 → 塔"趴"在墙头，比例仍然不对

**已全部删除，场地保持干净。** 建模资产保留在 `assets/out/SM_BG_*.fbx`，
下一轮重新设计摆放方案（关键是先把"地面 + 地平线 + 塔高"三者的关系算清楚）。

## 三、布光：这一轮最大的坑

### 症状

画面在"白成一片"和"全黑"之间反复横跳，改任何参数都像在掷骰子。

### 根因：两套布光代码在打架

| 路径 | 触发条件 | 曝光来源 |
|---|---|---|
| **正式布光**（实际生效） | 关卡太阳 ≥ 1000 lux | PPV 手动 bias，默认值在 `RobotCharacter.cpp:1315` |
| 救火路径 | 太阳 < 1000 lux | 另一处 bias，在 `FixLevelLighting` 后半段 |

我一直在改**救火路径**的那个值（`SunLux`、`bias -3.0`），而实际生效的是
正式布光路径的 `TargetBias`。这就是"改了没反应"的全部原因。

### 最终标定

```
太阳 22000 lux · 天光 3.2 · 点光 2600cd/1700cm
雾 0.0055（inscatter 0.022/0.030/0.046）
PPV：手动曝光 bias = 6.0
```

另外把三组早期调色补偿（`ColorGainShadows` 偏蓝、
`ColorGainHighlights` 偏暖、`ColorSaturation 0.88`）全部归中性 ——
它们是"画面发灰发橙"时期的补丁，现在布光修好了，反而把画面推成品红。

### 偏红的真正来源

**天空穹顶的太阳辉光色** `GLOW_COLOR = (0.45, 0.36, 0.28)`。
它被天光实时捕获成环境光，把地面、墙面、机体全部染暖。
改成 `(0.10, 0.12, 0.16)` 之后画面立刻回到冷调夜景。

这个坑值得记住：**天空穹顶的任何一个颜色都会变成全场环境光**，
它不是一个"背景图"，而是场景的主光源之一。

### 新增调试参数

| 参数 | 用途 |
|---|---|
| `-ScenicCam` | 高位斜俯视，看整块场地的布局 |
| `-ReviewEnemies` | 敌人检阅（摆一排 + 冻结 + 固定机位 + 检阅灯） |
| `-Bias=<值>` | 覆盖 PPV 曝光（扫光用） |
