# 迭代报告 · 2026-10-19

本轮针对三个已知问题：**运动动画有问题 / 纹理不符合场景 / 建模不够细致**。
三个问题都不是"再调一调参数"能解决的 —— 每一个底下都埋着一个结构性错误。

---

## 一、运动动画：从"正弦摆腿"到"两骨 IK + 脚掌锁定"

### 三个根因（都是查了才知道的）

**① 脚从来没有被"放在地上"，只是被"摆来摆去"。**
旧实现给髋角和膝角各写了一条经验曲线（髋 = 摆幅·cos、膝 = 6°+42°·sin），
脚的位置是两者合成的结果 —— 数学上**无法保证**支撑脚在世界里静止。
实测支撑脚以 40—80 cm/s 的速度在地面上滑，远看就是"踩在冰上"。

**② 骨盆起伏被放大了 100 倍（本轮最贵的一个坑）。**
FBX 进来之后，骨骼的局部位移单位是**米**（小腿 0.43），世界单位是**厘米**（小腿 43cm），
中间挂着一层 100 倍的骨架缩放。而 `OffsetBoneAxis` 直接往骨骼局部坐标里加"厘米"，
于是 3cm 的骨盆起伏变成了 3 米的下沉 —— 走起来时机体直接沉到地板下面。
旧版截图里"走路时机器人忽大忽小、位置飘"就是这个原因，只是当时归因到了相机上。
修法：缓存时用"小腿局部位移长度 / 小腿实际厘米长度"量出换算系数，所有平移乘上它。

**③ 调试侧视相机根本没生效。**
`APlayerController` 默认 `bAutoManageActiveCameraTarget = true`，会在 Possess 之后
把 ViewTarget 抢回 Pawn。调试相机建在 Possess 之前，于是日志写着"已接管视角"、
画面却还是第三人称背后视角 —— 这也是上一轮"改了轴向仍然觉得不对"的原因之一：
评估用的视角本身是错的。修法：关掉自动管理 + 每帧重申一次。

### 新实现（`MechProceduralAnim.cpp`）

| 模块 | 做法 |
|---|---|
| 步态周期 | 占空比 0.62（支撑 62% / 摆动 38%），相位差 0.5 |
| 步幅 | 由速度反解 `S = v·Duty·T`，超过腿长 92% 就自动提高步频（不让脚滑） |
| 脚的目标轨迹 | 支撑期**相对身体匀速后移**（与身体前进严格抵消）；摆动期 smoothstep 前送 + 正弦抬脚拱 |
| 两骨 IK | 余弦定理反解髋/膝：`α=acos((L1²+d²−L2²)/2L1d)`、`K=π−acos((L1²+L2²−d²)/2L1L2)`，膝盖朝前弯 |
| 脚掌俯仰 | 支撑期 −7°→+14°（脚跟着地 → 蹬地），摆动期 +16°→−8° |
| 骨盆高度 | 由**支撑腿**反推 `h=√(dMax²−fwd²)`，双腿取更大值 → 支撑脚正好落地，不穿地不悬空 |
| 骨盆侧摆 | 重心压向支撑腿 2.6cm，**平滑插值**（硬切会让整机一帧横跳 5cm） |
| 上半身 | 躯干前倾 5°、肩胯反向扭转 ±4.5°、手臂与同侧腿反相摆动（腿的 0.85 倍）+ 肘部随摆动屈伸 |

### 验收（日志 + 连拍）

- 支撑脚世界坐标在支撑期内**逐帧恒定**（例：左脚 X 连续三帧 = −166.7）
- 滑步指标（支撑脚世界位移速度）从 4000+ cm/s 降到 0—20 cm/s 量级；
  残留尖峰来自换腿那一帧，肉眼不可见
- 步幅 71.8cm、步频 7.6 rad/s（≈2.4 步/秒），髋 −53°…+3°、膝 15°…72° 的完整循环
- 侧视连拍（`docs/shots/f_*.png`）可见"抬脚—落地—换腿"三态

## 二、纹理不符合场景：材质**根本没挂上**

### 真正的根因

场景里有 **146 个静态网格构件（地面 / 墙 / 天桥 / 立柱）全部挂着引擎的
`BasicShapeMaterial`** —— 一块没有任何细节的浅灰塑料。

原因：竞技场是脚本重建的（`rebuild_arena.py`），生成 StaticMeshActor 之后
没有把材质重新指回去，而材质覆盖留在了组件上。
所以：

- 地面是一片均匀的浅灰，被 4200K 暖光一照就变成"沙漠色"
- 所有针对 `M_RobotSurface` 的调色、面板缝、金属度对它**完全无效**
- 机体（有材质）和场景（没材质）根本不在一个美术体系里 —— 这就是"不搭"的来源

修法（`ue/Scripts/fix_env_materials.py`）：补网格资产上的空槽 + 清掉 146 个
Actor 的 690 个材质覆盖，回落到网格自带材质。

### 第二个坑：磨损色把深色表面"洗白"

母材质的磨损色写死为 `base*0.5 + 0.45` —— 对深色表面（0.10）来说，
磨损色是 0.50，**亮了 5 倍**；而环境细节贴图的磨损通道本来就大面积偏亮，
于是整块地板被"磨损"洗成浅灰白，改基色完全没有反应（实测把环境钢从
0.15 调到 0.105，画面亮度一点没变）。

改成 `base*1.45 + 0.015`（相对基色），磨损才是"磨损"而不是"提亮"。

### 配色统一（`FORCE_COLOR` 表）

不再依赖 FBX 里的 DiffuseColor（重导时导入器会复用旧材质、颜色不更新），
改成在材质脚本里显式指定：

| 用途 | 颜色 | 理由 |
|---|---|---|
| 机体涂装装甲 | 0.30 / 0.31 / 0.34 | 冷灰蓝，在暖色场景里"跳"出来 |
| 机体裸露钢板 | 0.40 / 0.41 / 0.43 | 比装甲亮一档，边缘读得出层次 |
| 机体骨架/关节 | 0.075 / 0.052 | 保证装甲之间那条缝是黑的，分块才看得见 |
| 环境钢构 | 0.105 / 0.165 | 深钢灰，把画面重心让给主体 |
| 环境安全色 | 0.56 / 0.36 / 0.07 | 安全黄，工业场地的识别色 |

### 打光

投光灯的瞄准点从"地面"抬到 Z=170（机体胸口高度）—— 原来光锥中心全砸在地板上，
地板过曝、机体立面吃不到光。另外补了 4 盏 5600K 冷白补光（3.2m 高、不投影），
专门照机体立面，和 4200K 暖投光形成冷暖对冲。

## 三、建模：结构重做（v4）

旧版的问题不是"细节不够多"，而是**结构没有读出来**：所有主块都是轴对齐方盒，
加再多 greeble 也只是"一摞贴了零件的纸箱"。

| 改动 | 说明 |
|---|---|
| 梯形棱柱（`R.prism`） | 胸腔上宽下窄、大腿上粗下细、肩甲外张、小腿前倾 —— 剪影先对 |
| 骨架 / 装甲两层 | 深色内骨架永远比装甲小一圈，装甲板之间留缝，侧面能看见液压杆和线束 |
| 腿长 38% → 42% | 旧版又矮又墩；现在髋 134 / 膝 91 / 踝 28，站立比例正常 |
| 散热器收进壳体 | 旧版鳍片外挂 5cm 像"脱落的梳子"；现在是凹陷框 + 内嵌鳍片 |
| 关节护甲罩 | 护膝、踝护甲、肘罩、髋罩 —— 转动时不露接缝 |
| 武器细节 | 机匣 / 供弹 / 炮管 / 三道冷却环 / 制退器 / 炮口 |
| 左臂改为机械爪 + 传感吊舱 | 双臂都是炮管太单调；也符合"标准挂载接口"的设定 |
| 足部三段 | 脚跟（配重）+ 脚掌 + 脚趾，加防滑横纹 |

## 六、追加：把地图围起来（防掉出地图）

### 诊断

围墙其实是有的（`rebuild_arena.py` 沿四周摆了 30 段 `SM_Env_Wall`），
但"有围墙"和"掉不出去"是两件事，这里补了三层：

1. **碰撞确认**：`SM_Env_Wall` 有 1 个 convex 碰撞体，物理上确实挡人；
   但 FBX 自动生成的碰撞随导入设置变化，不能当作唯一保障。
2. **代码级硬边界**（`ARobotCharacter::ClampToArena`，每帧执行）：
   把角色钳在 `x ∈ [-1232, 1732]`、`y ∈ [-1312, 1312]`，
   并把**朝外**的速度分量清零、保留切向速度 —— 贴着墙走仍然是顺滑滑行。
   数值 = 围墙内侧面（-1277 / 1777 / ±1357）再减胶囊半径 45。
3. **掉落兜底**：Z < -300 判定掉出地图，拉回最近一次站稳的位置；
   敌人同理（掉下去会永远打不到、任务卡死），拉回出生点。

### 验证（实测日志）

```
# 走向 +Y 侧墙
[行走] t=8s 位置=(1102,1236,122) 速度=139
[边界] 撞到围栏：位置=(1179,1313,122) 速度=(99,0)     ← 侧向速度保留
[行走] t=10s 位置=(1179,1312,122) 速度=140

# 走向 +X 远墙
[边界] 撞到围栏：位置=(1733,-138,122) 速度=(0,0)
[行走] t=4s 位置=(1732,-138,122) 速度=0
```

两种朝向都被稳定拦在边界上，且贴墙滑行不卡死。

### 顺带加的调试参数

| 参数 | 用途 |
|---|---|
| `-WalkForever` | 一直走（原来只走 7 秒，走不到围墙） |
| `-WalkBack` | 朝 -X 走（验证后方围墙） |
| `-SpawnAt=x,y` | 改出生点（贴墙测试用；⚠️ 实测未生效，最终用 `move_spawn.py` 改 PlayerStart） |
| `ue/Scripts/move_spawn.py` | 临时挪 PlayerStart（环境变量 SPAWN_X/Y/Z/YAW） |

⚠️ `-SpawnAt` 在 BeginPlay 里没生效（原因未查明，日志里连分支都没进），
   最终改用"脚本挪 PlayerStart → 跑 → 挪回来"的方式验证。后续要用它得先查。

## 七、追加：真实墙体 / 曲面建模 / 贴图链路修复

### 1. 真实墙体（新资产 + 重新布墙）

旧墙是 4m 一段的方板（46 厚、两块面板），远看像一排灰盒子。新建：

| 资产 | 内容 |
|---|---|
| `SM_Wall_Segment` | 基座 → 墙体（两块凹板 / 四道外倾扶壁 / 检修口 / 通风格栅 / 铆钉）→ 外挑圆角压顶 → 顶部管线与管卡 → 底部安全色带 |
| `SM_Wall_Corner` | 90×90 转角柱：圆柱包角 + 压顶 + 警示带 + 顶部警示灯 |

`rebuild_walls.py`：删掉 30 段旧墙，按 4.0m 间距重铺 30 段（段长 4.12m，重叠 12cm 不留缝），
四角加转角柱。朝向按"内侧朝场地"旋转（背墙 yaw=90 / 远墙 -90 / 南墙 180 / 北墙 0）。

### 2. 贴图：两个硬故障（这才是"纹理不真实"的根因）

**① 细节贴图实际是 32×32 占位图。**
`T_MechDetail / T_EnvDetail` 的 `blueprint_get_size` 都是 32 —— 说明导入失败后
UE 留了一张占位图，而 `replace_existing=True` 对"源文件没变"的资产会跳过重建，
所以永远修不好。删掉四张图重导后恢复 1024×1024。

**② 三平面材质函数链路完全失效。**
把 `TextureSize` 120→40、`SeamDarken` 0.46→0.02、`WearTint` 改纯红，
**画面一个像素都不变**。函数节点的引脚连线在 Python 里读不出来，无法确认是否连上。
→ 改成 UV 采样，同时在 Blender 端把 UV 换成**世界对齐立方投影**
（`robotlib.cube_uv`，1 UV 单位 = 1.2m）：同一朝向的面共享连续 UV，
面板缝不再撕裂 —— 三平面本来要解决的问题在建模阶段就解决了。

### 3. 曲面建模

`robotlib` 新增 `ellipsoid`（可切半）、`torus`、`tube`（贝塞尔圆管）、
`capsule`、`rounded_box`；`build_chassis` 全面替换：

| 部位 | 之前 | 现在 |
|---|---|---|
| 肩甲 | 三层斜方板 | 半穹顶 + 弧形护壳 + 识别色收边环 |
| 头 | 方盒 | 圆角颅骨 + 头顶穹顶 + 弧面护额 |
| 四肢 | 方盒 | 圆柱（机械件）+ 弧面护甲壳 |
| 关节 | 圆柱 | 球窝 + 铜环（肩 / 肘 / 髋 / 膝 / 踝） |
| 脚 | 方盒 | 圆角脚掌 + 半椭球趾 |
| 背包 | 方盒 | 圆柱储罐（胶囊） |

三角面 28.8k → 48.9k（LOD0），三台机体一致。

### 4. 布光：发现"救火代码"在覆盖正式布光

`FixLevelLighting()` 是早期黑屏时写的救火代码：把太阳压到 **6 lux**、天光 0.22、
后处理改成手动曝光 bias 8.8。它会把 `relight.py` 的正式布光（30000 lux / 2.2 / EV13.6）
全部覆盖 —— 材质怎么调都发灰发白，根子在这里。

已加判定：太阳强度 ≥ 1000 lux 视为"已正式布光"，跳过覆盖，只强制 PPV 无界。
⚠️ **但正式布光路径下 PPV 曝光还没调对**（EV13.6 下画面过曝成黄色），
所以暂时仍走旧路径（bias 由 8.8 调到 6.6）。这是下一轮要收尾的第一件事。

## 八、追加：布光根因（2026-10-22）

前几轮一直有个说不清的问题：**材质怎么做都发灰发橙**。这轮找到了根因：

### 1. 天光捕获不到天空

引擎在画面上直接打了一行红字：

> A sky light with real-time capture enable is in the scene. It requires at least
> a SkyAtmosphere component, a VolumetricCloud component **or a mesh with a
> material tagged as IsSky**. Otherwise it will be black.

也就是说：SkyLight 开着实时捕获，但场景里**没有任何东西被标记为"天空"** ——
自建穹顶的材质只设了 `used_with_sky`，没有设 `is_sky`。
结果天光捕获到的是黑色 → 环境光接近 0 → 整个场景只剩几盏暖色灯直射，
暗部没有冷色补光，于是"又平又橙"。

修法：`M_SkyDome` 设 `is_sky = True`。改完之后天空真的出现了，
环境光也有了来源，画面立刻有了方向感和暗部层次（见 `11_布光修复后.png`）。

### 2. 灯全是钠灯橙

15 盏点光是早期用 2000K 钠灯搭的，`relight.py` 只改强度没改色温，
叠在一起把地板、机体、墙全染成橙色。
→ `fix_light_color.py`：点光统一 5200K / 1400cd，投光 5000K。

### 3. 泛光阈值是负数

`BloomThreshold = -0.35` 意味着**连中灰都会泛光**，亮面糊成一片白雾。
→ 改成 1.0，强度 0.45。

### 4. 太阳强度可调

`FixLevelLighting()` 里写死的 6 lux（救火时期的量级）改成 `-SunLux=` 可调，
默认仍保守。曝光 `-Bias=` 也可调（手动曝光是实测唯一有效的路径）。

### 5. 仍未解决

- 天空穹顶的**太阳辉光**还没调好：现在天空是干净的暗色，但"黄昏"氛围弱了
- 逆光面偏白（材质 albedo 0.30 + 强主光），需要再压 0.5 档曝光
- 这些都需要一次**专门的布光迭代**，不是顺手能改完的

### 6. 下一步（玩法）

美术这条线暂时收在一个"能用"的状态，接下来转玩法：
敌人 AI 现在还是"直线接近 + 开火"，要加侧移/掩体；以及受击反馈、死亡演出。
