# 迭代报告 · 2026-10-23（第六轮）：UV 归一化 bug

本轮目标：修掉"机体表面都是网格"。

---

## 一、真因：`cube_project` 会把 UV 归一化到 0~1

上一轮把纹理换成 4K 之后，机体表面反而变成一片细密网格。查 UV 范围：

```
UV 范围  u: 0.000 ~ 1.000    v: 0.000 ~ 1.000
```

机体高 2.7m，UV 却只有 0~1 —— 说明 **`bpy.ops.uv.cube_project(cube_size=1.2)`
根本没按世界尺度算 UV，而是把结果归一化了**（`scale_to_bounds=False`
也没用，这个操作符本身就是先投影再适配到 0~1）。

后果：一张 4K 贴图铺满整台机体。贴图里 3×3 的板缝网格被拉到
**每块 90cm** —— 远看是一片纯色（"没有纹理"），近看就是粗大的网格线。

这也解释了上一轮的困惑：换 4K 之后"更糟"，因为 1024 时代的板缝本来就粗，
4K 把同一个网格渲染得更清晰了。

---

## 二、修法

### 1. 手写立方投影

不再用 `cube_project`，自己按面算：

```python
for poly in me.polygons:
    ax = 主轴（法线绝对值最大的轴）
    for li in poly.loop_indices:
        v = world_matrix @ vertex.co
        u, w = 按主轴选两个分量（X→YZ, Y→XZ, Z→XY）
        uv[li] = (u / size_m, w / size_m)
```

同时**清掉多余的 UV 层**（原来 join 之后有 2 层，材质用 UV0 但内容是旧的）。

修复后：
```
UV 范围  u: -0.707 ~ 0.707    v: -0.392 ~ 2.243
UV 层数: 1
```

高度方向 2.2 个贴图单位 —— 这才是"贴图按真实尺度重复"。

### 2. UV 尺度 1.2m → 3.2m

1.2m 铺一张 4K，在 1.7m 宽的机体上会重复 1.4 次，板缝太密。
改成 3.2m 之后约 1280 px/m，板缝间距约 1m —— 和真实装甲板尺寸相当。

### 3. 板缝压暗 0.46 → 0.16

`SeamDarken=0.46` 会把缝压成纯黑，看起来像"贴了网格纸"。
真实装甲的板缝是**阴影**不是黑线，0.16 刚好。

## 三、修复前后

| | 修复前 | 修复后 |
|---|---|---|
| UV 范围 | 0 ~ 1（归一化） | v: -0.39 ~ 2.24（按尺度） |
| UV 层数 | 2（材质用了旧的那层） | 1 |
| 贴图尺度 | 一张铺满整机（板缝 90cm） | 3.2m 一个循环（板缝约 1m） |
| 板缝压暗 | 0.46（纯黑） | 0.16（阴影） |
| 观感 | 密集马赛克网格 | 大块装甲面 + 轻微色差 |
