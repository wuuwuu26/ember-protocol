# 迭代报告 · 2026-10-23（第四轮）：纹理没加载出来 + 全面 4K

本轮目标：查清"纹理没加载出来"，把所有场景纹理升到 4K。

---

## 一、诊断：确实是贴图坏了，而且坏得很彻底

探针结果：

```
T_MechDetail     32x32     ← 机体所有材质都用它
T_MechDetail_N   32x32
T_EnvDetail      1024x1024
T_EnvDetail_N    1024x1024
```

**机体的细节贴图是一张 32×32 的空白图**。也就是说这一路以来的"机体表面有面板缝"
其实全靠程序化材质的 SeamDarken / WearAmount 在硬算，贴图本身没有内容。

### 为什么会一直卡在 32×32

UE 的 FBX/贴图导入器对**"源文件没变"的资产会跳过重建**。
某一次导入失败时 UE 留了一张 32×32 占位图，之后无论 `replace_existing=True`
跑多少遍，它都认为"源文件没变化"而不重建 —— 这张占位图就永久固化了。

**唯一解法是先把资产删掉，再导入。**

### 为什么之前"看起来有纹理"

材质里 `DetailTex` 参数在 MI 上是绑了 `T_MechDetail` 的（绑定本身没问题），
但那张图是 32×32 的纯灰，采样出来就是一整片均匀的灰度 ——
相当于"没有贴图"。板缝、铆钉那些视觉线索全来自材质的程序化项。

## 二、生成 4K

生成器 `make_detail_texture.py` / `make_env_texture.py` 的 `SIZE` 从 1024 改到 4096。

**关键**：所有"按像素写"的参数必须乘 `S = SIZE/1024`，否则 4K 下缝宽还是 16px ——
在 1.2m 的 UV 尺度上只有 4.7mm，远看直接消失。

| 参数 | 1024 基准 | 4K 实际 |
|---|---|---|
| 主板缝宽 | 16px | 64px |
| 分板缝宽 | 10px | 40px |
| 细刻线 | 5px | 20px |
| 铆钉半径 | 5.5px | 22px |
| 刮痕长度 | 30~230px | 120~920px |
| 刮痕数量 | 46 | 92（面积比应是 16 倍，但全图计算太慢，取 2 倍并加长） |

`fbm` 的频率参数与分辨率无关（它按"每张图几个周期"算），所以保持不动 ——
4K 会自动得到更细的噪声。

生成耗时：机体 3.5 分钟、环境 2.5 分钟（numpy 全图运算）。

## 三、导入设置（这才是"加载不出来"的另一半原因）

`reimport_tex.py` 重写，做了四件事：

| 设置 | 值 | 为什么 |
|---|---|---|
| 先删再导 | — | 绕开"源文件没变就跳过重建"的坑 |
| `max_texture_size` | 4096 | 默认可能被压到 2048 |
| `never_stream` | True | 4K 默认走 texture streaming，某些画质档只加载低 mip —— **看起来就是"没加载出来"** |
| `compression_settings` | `TC_GRAYSCALE`（法线仍 `TC_NORMALMAP`） | 灰度细节图用 MASKS/DXT 会有块状压缩 |

四张图共约 80MB 显存，直接常驻。

## 四、顺带修的两个脚本 bug

1. **`make_detail_texture.py` 缺 `if __name__ == "__main__"` 保护**
   → `make_env_texture.py` 只是 `import` 它，就触发了整个机体纹理生成，
   白跑 3 分钟才发现真正的错误。

2. **`tileable_gradient` 函数不存在**
   `make_env_texture.py` 从 detail 脚本 import 它，但它早就被删了 ——
   所以环境纹理这条线其实一直是断的。
   补回实现：用 `np.roll` 做环绕差分，保证贴图边界的切线也连续（否则平铺时法线有亮边）。

## 五、关于"用 UE5 自带资产"

我查了本机引擎自带的内容，能直接用的 4K 纹理非常有限：

| 路径 | 内容 | 能否用 |
|---|---|---|
| `/Engine/EngineSky/T_Sky_Blue` | 15MB 天空图 | 已用其同类（`T_Sky_Stars` 做星空） |
| `/Engine/EngineSky/T_Sky_Clouds_M` | 云层遮罩 | 可用，但本项目是夜景，暂时不需要 |
| `/Engine/StarterContent/Textures/` | **只有 1 张** `T_ground_Moss_D` | 苔藓地面，和工业场地不搭 |
| `/Engine/EngineMaterials/` | 材质为主，无通用 4K 表面纹理 | 用不上 |

**引擎没有"工业金属/混凝土"这类表面细节纹理** —— StarterContent 在这台机器上
只装了一张贴图。所以表面纹理只能程序化生成，这也是为什么这套管线一开始
就写了 `make_detail_texture.py`。

引擎资产真正帮上忙的地方是**天空**（`T_Sky_Stars` 接进 `M_SkyDome`，上一轮做的）。
